# 通知履歴の詳細画面 Implementation Plan

> Execute with superpowers:executing-plans. User approved the switching design and implementation.

**Goal:** 一覧と詳細を同じ幅で切り替え、日本語の診断説明・発生版・初回/最終発生/復旧時刻を表示する。広告404の記録を保持し二重記録だけを修正する。
**Architecture:** Policyが追加メタデータを検証、Journalが発生時の値と集約時刻を所有、Panelが表示を所有。既存DBと保存キーを維持。広告404はユーザーの追加指示により全て記録し、正常/故障と断定しない。
**Tech Stack:** TypeScript正本、既存nico生成、Mocha/jsdom、オフラインChrome。
**Spec:** 今回のユーザー指示と承認された「一覧から詳細へ」の案。既存の暗い配色・外側クリック閉じ・アニメーションを維持。

- [ ] 版番号・初回/最終発生・復旧時刻をJournal/Policyへ追加。古い記録は不明と表示し推測しない。反復失敗と復旧の時刻をテスト。
- [ ] 広告thanksのHTTP/JSON404を保持し、500・401・ネットワーク・不正応答も記録。同じ応答を1件だけ記録する実配線テスト。
- [ ] Panelは一覧/詳細の切替、検索/分類/戻り位置、技術情報折畳み、報告文コピー、管理操作折畳み、単一スクロール。選択中の復旧更新・削除・失敗・フォーカスのテスト。
- [ ] 型/生成/関連/全体回帰・独立レビュー・Chrome検証、版2.7.370-task994、公開/非公開へ反映してリリース。テスト用Chromeを閉じる。

**Review focus:** 古い履歴の欠落項目、復旧で最終失敗時刻を上書きしない、対象外404の保持、更新時の選択とスクロール、消去後の古い非同期描画。

Ruling: ユーザーは対象なし404も残す方針へ変更。既知のスポンサーなし応答も除外せず、広告取得境界が単一記録を所有する。
