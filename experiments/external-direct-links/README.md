# 外部ページで直接リンクから開く検証版

対象は HTTP(S) の www.nicovideo.jp/watch/動画ID と sp.nicovideo.jp/watch/動画ID への直接リンクのみ。
外部サイト内のリンク、文字列の動画ID、短縮・転送リンク、サムネイル照合は対象外。
元のリンク・ページURLは変更せず、独立した Zen ボタンを追加する。

## 検証版3の変更

検証版4では、共通ライブラリを親ページだけに渡していた初期化を修正。実際に子フレームを作り、window._ がなくUserscript内だけに依存がある条件で停止を再現して修正を検証した。起動中の段階表示と、安全な段階名によるエラー表示も追加。

プレイヤー全体をニコニコ側の別文書（iframe）で表示します。外部サイトのCSSはプレイヤー文書へ届きません。外部ページにはZenボタンと表示枠だけを置き、コメントのDOM変更をリンク監視で処理しません。API・HLS通信は引き続きGM経由です。

いいねなどが参照する util.isLogin も認証結果に同期し、入力保護は実際のプレイヤー要素ができた時点で設定します。終了通知で外部ページ上の表示枠を取り除きます。

独立文書での起動・GM通信と私有チケットによる開閉をオフライン検証済み。実ブラウザでの見た目・操作・軽さは要確認です。

HAR はローカルで構造の確認にだけ利用し、このフォルダーや Git に含めない。

## インストールと戻し方

[検証版をインストール](https://raw.githubusercontent.com/ButaMonky/ZenzaWatch/experiment/external-direct1008/experiments/external-direct-links/ZenzaWatch-external-direct-trial.user.js)

`ZenzaWatch-external-direct-trial.user.js` を Tampermonkey に別スクリプトとして追加してください。
通常の ZenzaWatch は削除・置換しません。検証版名は「ZenzaWatch 外部直接リンク検証版」、版は `0.9.0-external-direct9` です。旧検証版へ上書き更新してください。
Tampermonkeyの接続先権限はニコニコ関連の3ドメインに限定しています。サイト別Cookie許可は追加しません。Tampermonkeyから権限確認が出る場合は、この通信機能のための確認です。
対象サイト上のリンクを探すため HTTPS サイトへのアクセス権限を使用します。ページを開いただけでは本体の起動・認証通信は行いません。
元に戻すときは検証版だけ無効にし、ニコチャートを再読み込みしてください。

## 確認するところ

1. 更新後、ログイン済みのニコニコ公式ページを一度再読み込みして設定を取り込んでから、ニコチャートまたはニコログの動画詳細ページを再読み込みする。サイト別Cookieの許可は追加せず試す。
2. 動画タイトルとサムネイルの直接リンクの横に「Zen」が出る。通常のリンクは従来どおりニコニコへ移動する。
3. 「Zen」で同じニコチャートのページ上にプレイヤーが開き、URLが変わらない。
4. 動画とコメントが再生され、別の「Zen」を押してもプレイヤーが増殖しない。
5. ご自身で選んだ動画で、いいね・あとで見る・マイリストを操作し、公式ページにも反映されることを確認する。
6. 投稿したいコメントがある場合だけ投稿し、成功表示と実際の反映を確認する。検証用の自動投稿はしない。
7. ニコニコ側の視聴履歴に残るか確認する。ブラウザや第三者拡張機能の履歴は今回の確認対象ではない。
8. プレイヤーを閉じると元のページを操作できる。検証版を無効化して再読み込みすると追加ボタンが消える。

認証確認の案内だけが出た場合は、その文面を共有してください。HAR全体やCookieを送る必要はありません。
401・403・GM通信失敗・時間切れを区別して表示します。拒否が続く場合、Cookieやパスワードをコピーせず案内文を共有してください。
実ブラウザで第三者Cookie拒否時の動作はまだ未確認です。埋め込みを禁止するサイトでは設定用フレームなどが制限される場合があります。

## 検証版6の設定修正

- 自動起動の抑止と上級者設定の登録を分離し、本体のコントローラーを復元。
- HLS・通常設定は本体の同じ実装を利用。部品名を検証版専用にして、他の版が先に登録した部品を再利用しない。
- 本体の既定値宣言から取り込み対象を抽出。HLS、フィルター、ショートカット、ヘッダー位置も対象。検証版の変更は250ms単位でまとめて保存し、閉じる時に確定する。複数ページでは変更した項目だけを統合する。
- HLSのバッファ・画質設定は本体の案内どおり次の動画から適用。認証通信のため外部版はhls.js固定で、ネイティブHLSの指定は使わない。
- コメント増量パネルの埋め込み画面検索を、iframeの追加・削除時だけに制限。通常の画面更新20回で走っていた20回の検索は、対象外の更新では0回になることを試験。体感速度は未確認。
- 自動試験は、生成済み本体で上級者設定の実際の画面を生成し、通常設定の入力処理、HLS設定の更新通知・保存・再読み込み、古い部品との分離、複数ページの保存競合を確認。実ブラウザでの見た目・再生中の反映は利用者確認が必要。

### 検証版6の確認手順
1. 検証版を更新し、通常版を使っているニコニコ公式ページを一度再読み込みする。
2. 外部サイトを再読み込みしてZenを開く。通常設定・HLS設定・上級者設定が開くか確認。
3. メニュー倍率などを一項目変更し、反映を確認。上級者設定は保存、HLS設定も保存を押す。HLSは次の動画で確認。
4. 閉じて再度開き、変更が残るか確認。別の外部サイトでも同じ設定になるか確認。通常版の設定は勝手に変わらないことも確認。
5. コメント増量・しおり・通知・画面フィルターの開閉が引っかからないか確認。重さ全体の解消を保証する段階ではない。

## 検証版7：未解決の操作遅延・設定引き継ぎの診断

ユーザー確認では検証版6でも操作が重く、既存設定が反映されない。検証版7は原因確定のための計測を追加する版であり、解決済みとは扱わない。

更新後、公式ページを再読み込みし、外部サイトも再読み込みしてZenを開く。プレイヤー内の最初のクリックから15秒間、重いパネル操作を行う。Consoleに出る ZENZA_UI_DIAG のJSONを共有する。コピー用の式を実行する必要はない。

記録内容：固定されたイベント種別ごとの最大入力待ち時間・処理時間・処理終了後の遅延、長い処理の集計、フレーム間隔、タイマー遅れ、設定取得件数・本体との不一致項目名。設定値・コメント本文・URL・動画ID・Cookie・通信内容は記録しない。結果はConsoleだけに出し、通信や永続保存はしない。

Event Timing のdurationは丸めや閾値の影響があり、処理終了後の値を純粋な描画時間と断定しない。iframeやブラウザによる計測制限もある。hiddenDuringSampleがtrueの記録は非表示タブによる抑制を含む可能性がある。計測は一度のみで、終了時に監視とタイマーを解除する。再計測はプレイヤーを閉じて開き直す。
