## 目的と承認範囲

場面を探すときに、サムネイル、その場面のミニコメント、操作できるコメント一覧を迷わず使えるようにする。

ユーザーは既存02〜10を十分確認していなかったため、全11方式の維持より、用途が明確なUIへの作り直しを希望している。方式数の削減と上級者設定の名称・表示の再設計を許可した。

「追従」「固定」の2方式と、別枠の「従来表示」を基準に画面案・設計書を作る方針は承認済み。本書はその具体化であり、製品実装は本書の確認後に計画する。

共通設定として背景濃度0〜100%（初期90%）、サムネイル倍率50〜200%（初期100%）、コメント表示の親スイッチとミニ／一覧の子スイッチも承認済み。全方式、通常・全画面に共通で適用する。

既存304のUI02は配置・一覧操作・表示維持・自動非表示が実機OK。新UIや新設定の実機確認済みという意味ではない。

## 表示方式と操作

| 名称 | 用途 | 配置と動作 |
| --- | --- | --- |
| シーク位置に追従 | シークしながら場面を探す | シーク位置の上に画像と任意の一覧をひとまとまりで表示。画面端では全体を止める。 |
| 位置を固定 | 同じ場所で画像や一覧を見ながら調べる | 通常は動画直下の空き領域の左側。収まらない場合と全画面はプレイヤー内の左下、操作バーの上。シーク位置で左右移動しない。 |
| 従来表示〈互換用〉 | 旧版の操作を継続する | 元のサムネイル＋ミニコメントと一覧を切り替える。元の描画・操作主体を維持する。 |

新2方式は同じ表示部品・操作を使い、位置の決め方だけ分ける。一覧はサムネイルのすぐ右隣に置き、画面の左右両端へ分離しない。

- ミニコメントは画像の上に重なる。
- コメントボタンで一覧を開閉する。新2方式では画像とミニコメントを残す。
- 一覧のスクロール、時刻クリック、NG操作は既存の実装を利用する。
- 一覧を設定でOFFにした場合、コメントボタンを無効化して理由を補助説明に示す。
- ミニだけOFFでも、画像と一覧を利用できる。
- 追従中にシークバーからプレビューへマウスを移したら位置を維持し、シークバーへ戻ると追従を再開する。
- 「位置を一時固定」は現在の場面と位置を保つ。固定方式は表示位置を一定にしながらシーク内容を更新する。この違いを説明する。
- 既存の動画クリック・シーク・ホイールの操作主体を変えない。
- 全画面では実際の全画面要素の中に配置し、外へ取り残さない。

### 小画面モードでの固定配置（調査に基づく追加案）

Zenzaの「小」はブラウザーの別窓PiPではなく、ページ内を移動・拡縮できる動画。既定400×225、最小160×90で、動画とコメント層に移動用transformが付く。一方、シークバーはブラウザー下端に固定される。親containerの矩形は動画のドラッグ後も元の位置を返すため、小画面の見た目の位置として使わない。

採用候補は「動画枠への固定」ではなく「シークバー付近の空き領域への固定」。通常の固定配置とは座標の基準を変え、表示方式を増やしたり追従へ勝手に切り替えたりしない。小画面では通常表示側の方式設定を使う。実際の全画面中は全画面側の配置を優先する。

1. ブラウザー内の表示可能領域とシークバーの実寸から、バー直上・左寄せを第一候補にする。画像とmini、任意の一覧を一体で配置する。
2. 見えている動画や操作部と重なる場合、右寄せを試し、両側とも難しければ他の空き領域を探す。現在位置が安全なら維持し、シークするたびに候補を選び直さない。
3. 一覧への移動中、hover、キーボードフォーカス、一覧操作、ピン中は位置を保つ。動画のドラッグ・リサイズでもプレビューを逃げ回らせず、操作終了後に再配置する。ブラウザー縮小で画面外になる場合だけ境界内へ補正する。
4. 余白が足りないときは画像とminiを一緒に縮め、一覧の幅・高さを制限して内部スクロールを使う。操作ボタンと一覧文字を縮めず、保存した倍率や個別ON/OFFは変えない。画像と一覧の同時表示を維持する。
5. 動画が画面の大半を占める等、操作可能な最小サイズのパネルを置ける空き領域がない場合、映像との重なりを最小にした省スペース表示を許容する。映像との非重複を常に保証することはできない。シークバー・閉じる・サイズ変更・フォーカス中の入力やメニューを優先し、操作可能な層順を保つ。

固定とは「シーク位置では動かさない」の意味とする。小画面の移動やブラウザーのサイズ変更で必要になる補正は許容する。小画面自体を勝手に移動・拡縮しない。

実装時は通常／全画面の設定選択とは別に、smallなど実際のプレイヤー状態を配置へ伝える。現状の SceneSearchPlayerBinding は全画面以外をnormalにまとめるため、その二値だけで配置を決めない。動画の実際の矩形、シークバー、コメント入力欄と展開中のコマンド欄、閉じる・リサイズ等の可視操作部をそれぞれ測る。ドラッグ終了・リサイズ終了・モード変更・入力の展開を再評価の契機とし、毎マウス移動で強制レイアウトや常時監視ループを追加しない。

新2方式の共通プレビューは、移動用transformの影響を受けない座標系に置く。親containerへtransformを追加しない。画面全体を覆う層はpointer-events:none、実際のパネルだけ操作可能にし、旧位置の透明な領域へ当たり判定を残さない。全画面移行では配置先と座標系を更新し、閉じる際に要素・購読を解放する。従来表示のnative所有関係は別途維持する。

調査根拠: src/CONSTANT.js、src/NicoVideoPlayerDialog.js の _initializeSmallModeDrag と for-popup CSS、src/VideoControlBar.js の固定バー、SceneSearchPlayerBinding._mode、SceneSearchIntegrationBridge のUI02配置。既存CSSを使った独立Chromeの最小DOM検証で、動画を(840,430)へ動かしてもcontainerは(0,0)、バーは幅1280の下端に残ることを確認した（4ケース・32検査）。製品全体の小画面実機合格を示すものではない。現在の画面案は通常／全画面の見本で、この追加案の小画面配置は未反映。

### 狭い画面

画像と一覧は横並びを維持し、列幅と画像倍率を利用可能な空間に制限する。画像の縦横比とminiの相対位置を変えず、操作ボタンと一覧の文字は縮小しない。操作列は必要な幅を確保し、一覧の長文は省略表示と通常のスクロールで扱う。保存した倍率は書き換えない。

## 上級者設定

「画面・映像 → シーンサーチ」を次の順に整理する。

1. 通常／全画面タブと、動作を表す見本付きの2つの表示方式カード。
2. 「全画面も同じ表示方式を使う」。方式だけ連動し、以前の全画面用選択を保持する。
3. 折りたたんだ「旧版との互換」に「従来表示を使う」。11枚の番号付きカードは廃止。
4. 「シーンサーチのコメント表示」の親スイッチと2つの子スイッチ。
5. 一覧背景の濃さ、サムネイルの大きさ。
6. 共通の自動非表示時間、既存のシーク秒数・操作ボタン設定。

ON/OFFは既存の上級者設定と同じトグルスイッチを使い、項目名を左、スイッチを右に配置する。丸いつまみ、ON/OFFの配色、余白、子項目の字下げと無効時の薄い表示も既存デザインに合わせる。製品実装では既存の設定部品を再利用し、シーンサーチだけ異なる操作体系にしない。

初期値と異なる項目は、既存の is-modified と同じ控えめな青い縁・光で示す。判定対象は保存前後を問わず現在の設定値と初期値の差であり、未保存の印とは分ける。初期値へ戻したら光を消す。親がOFFでも子の保存値を変えず、子の無効表示と初期値との差は両立させる。

「画面・映像 → 表示・非表示」にも「シーンサーチ」のまとまりを設け、親スイッチ、ミニコメント、コメントプレビューを親子順で置く。シーンサーチ画面と同じ設定ID・編集中の値・初期値を参照し、別の保存キーを増やさない。どちらから変更・初期値への復帰・キャンセルをしても、もう一方のチェック状態、親子の有効／無効、青い変更表示を同期する。保存済みの変更は再度開いても青く表示する。

今後の表示関連項目も、正本の設定定義と表示・非表示の一覧登録を一緒に更新する。既存の UiVisibilityRegistry と設定の参照表示を利用し、名称・説明・分類・並び順・親子依存を一致させる。説明内の項目数を固定したまま追加せず、実数に合わせる。倍率や背景濃度など見た目を調整する数値はシーンサーチに配置し、表示を切り替える項目との違いが分かるようにする。

抽象的な愛称やUI番号を選択名にしない。見本には画像上の文字と隣の一覧を描き、実際の動作と一致させる。設定画面の見本は編集中の値で変わるが、実プレイヤーには「変更を保存」で反映する。キャンセルでは変更せず、保存後のページ再読込は不要。

| 表示名 | 保存キー | 初期値・範囲 |
| --- | --- | --- |
| シーンサーチのコメント表示 | sceneSearch.commentPreviewVisible | true |
| ミニコメントを表示する | sceneSearch.miniCommentVisible | true |
| コメントプレビューを表示する | sceneSearch.commentListVisible | true |
| コメント一覧の背景の濃さ | sceneSearch.commentListBackgroundOpacity | 90%、0〜100%の整数 |
| サムネイルの大きさ | sceneSearch.thumbnailScale | 100%、50〜200%の整数 |
| プレビューを自動で隠すまでの時間 | sceneSearch.idleHideSeconds | 既存値を維持。初期2秒、0で無効 |

親OFFは両方を実効OFFにし、子のチェック値を保存したまま入力を無効化する。親ONで復元する。子の一覧ONだけでは勝手に一覧を開かず、コメントボタンによる開閉を使う。子の一覧OFF中は画像表示を利用し、以前の一覧モード要求を消さない。

背景濃度は背景色のalphaへ適用する。一覧全体や文字のopacityを下げず、操作中も背景だけ勝手に100%へ変えない。0%でも文字と操作状態は判別できる。動画本体のコメント設定には影響させない。

## 画像とミニコメントの拡縮

- 画像とminiを共通の論理座標へ揃え、外側で一度だけ等比拡縮する。
- コメント行だけを別々に配置し直したり、文字サイズだけを変えたりしない。
- 既存Storyboardのcanvas解像度、画像キャッシュ、worker数を変えず、表示倍率を変更する。
- 占有寸法も更新し、当たり判定、一覧の隣接位置、画面端制限に実寸を使う。
- 時刻、操作ボタン、一覧文字は画像の倍率から分離する。
- 従来表示は元のDOM所有関係を維持し、画像と兄弟のminiに同じ基準の座標変換を適用する。
- ピン中、全画面移行、画面サイズ変更、画像の後着でも位置を再確認する。

画面案の文字は見本。実際のコメントアートの再現性は、元の描画・時刻・フォント・改行を使った別の検証で確認する。

## 自動非表示と当たり判定

時間設定は画像・mini・一覧で共通にする。

- シークバーで同じ場面を表示し続ける場合に既存の待機時間を使う。
- サムネイル、一覧、操作ボタン、メニューを操作中は隠さない。
- キーボードフォーカス、ドラッグ、ピン固定も表示を維持する。
- プレビューへ移る短い移動経路を保護し、途中で消さない。
- 離れた領域全体を透明な当たり判定で覆わず、動画の操作を奪わない。
- 非表示後に再びシークすると最新の場面で復帰する。

固定／追従で座標計算は分けるが、表示維持条件は共通の状態管理へまとめる。

## 既存設定の移行案

新しい意味ベースの保存値を設け、旧番号を表示名として再利用しない。

- 新規利用時は通常・全画面とも追従を初期値とする。
- 旧00は従来表示、旧01・06は追従、旧02・03・04・05・07・08・09・10は固定を移行候補とする。
- 旧番号と関連値は削除・上書きしない。正常な新形式の選択があればそれを優先する。
- 対応が変わる場合、設定画面に旧名称と新方式を一度表示する。ユーザーは2方式か従来表示を選び直せる。
- 3コマ、特殊な引き出し、分離リモコン、自動回避を独立した方式として維持しない。必要になった機能は用途を確認して再検討する。
- 確認用ブランチで作り、実機確認後に置き換える。304は比較・復帰用に保持する。

既存のミニ設定（sceneSearch.miniCommentMode）も移行する。新しい子スイッチがまだ保存されていない場合、旧hiddenはミニOFF、旧flowはミニON＋流れる表示、旧staticはミニON＋静止表示として解釈する。新しい子スイッチが保存済みなら、その値を表示可否の優先値とする。旧hiddenから子をONにした場合は流れる表示へ戻し、旧staticの利用者はON/OFFを繰り返しても静止表示を保つ。旧値そのものは削除しない。

既存の静止表示は詳細な互換設定として引き継ぎ、新2方式でも同じ意味で扱う。主な表示方式を増やす理由にはしない。保存値の有無と、Configの既定値による読み取りを区別し、旧hiddenの利用者へ意図せず再表示しない。

この対応表も本書の確認対象。新UI完成前の既存方式削除や、自動切り替えは行わない。

- 親子の組み合わせ、保存・再読込・リセット・JSON入出力、不正値の拒否。

- 背景0／40／90／100%、倍率50／100／150／200%、100%へ戻したときの復元。

- 幅320／768／1536相当、シーク先頭／中央／終端、画面サイズ変更、ピン中。
- 画像とminiの基準と等比拡縮、文字位置・流れ、canvas解像度の不変。
- 新2方式の画像＋mini＋一覧同時表示、一覧のスクロール・時刻クリック・NG操作。
- 操作中の表示維持、移動経路、非表示からの復帰、動画操作との共存。

- 新しい子設定が未保存／保存済みの場合それぞれで、旧flow／static／hiddenの移行と、親・子のOFF→ON後の表示方式を確認する。
- 動画切替、方式切替、破棄時のnative要素復元とlistener／timerの解放。
- 元の描画を使うブラウザー確認、適切な単体・全体テスト、生成物の再現性。
- 実際のニコニコ画面でユーザーが新方式を確認してから次へ進む。

## 今回の確認対象

追従／固定の見た目、画像の隣に一覧を出す配置、固定方式の置き場所、上級者設定の分かりやすさ、旧方式の移行候補。

画面案は配置と設定を検討するための見本。動画再生、実機のコメント描画、自動非表示タイマーの製品実装は含まない。画面案の通常表示では動画直下に空間がない場合の配置を示している。
